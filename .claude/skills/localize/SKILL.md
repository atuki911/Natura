# 日本向け深掘り（localize）

`data/cases/<事例ID>.json` の海外事例を、日本で個人が再現するための調査レポートにする。
外部の有料APIは使わない。調査には Claude Code の WebSearch / WebFetch だけを使う。

## 手順

1. **土台を作る**：`npm run report -- <事例ID>` を実行し、ツールが自動生成した日本版プラン（`reports/<事例ID>-<日付>.md`）を読む。相性診断の条件を使う場合は `--profile profile.json` を付ける。
2. **日本の競合調査**：日本語で WebSearch を最低4回行う。例：
   - 「<カテゴリのキーワード> AI サービス」「<海外サービス名> 日本」「<課題> 自動化 ツール 料金」
   - 「site:prtimes.jp <キーワード>」で国内の新サービス発表を探す
   見つかった国内サービスは、名前・URL・価格・対象顧客・特徴を表にする。**実在を確認できたものだけ**載せる。
3. **需要の手がかり**：検索結果の数や Q&A サイト・X での悩みの声、関連する市場統計（官公庁・業界団体の公表値）を出典付きで集める。
4. **価格の妥当性**：国内競合の価格と比べ、ツールが出した推奨価格を見直す。
5. **規制の確認**：レポートの「法規制チェックリスト」のうち重要度4以上の項目について、所管省庁の一次情報を検索し、該当しそうか・何をすべきかを具体化する（法的助言ではないことを明記）。
6. **レポートを書き足す**：自動生成のレポートの末尾に次の節を追加する。
   - `## 15. 日本の競合（調査結果）`（表と出典）
   - `## 16. 需要の手がかり`
   - `## 17. 推奨する日本版コンセプト（最終案）`：ターゲット、提供価値、差別化、価格、最初の10人の獲得方法
   - `## 18. 撤退基準`：何をいつまでに達成できなければやめるか
7. **事例データへの反映（任意）**：調査で `categories.json` の `knownCompetitors` や事例の `japan.notes` を更新すべき事実が見つかったら更新し、`npm run validate && npm run build && npm test` を通す。
8. **報告**：レポートのパスと、最終案の要点を3行でユーザーに伝える。

## 注意

- 推測と事実を区別し、数字には出典か「仮定」を付ける。
- 競合の機能・価格は変わるので、確認日を書く。
